ABSTRACT
================================================================================

LabourBridge is a comprehensive mobile application designed to bridge the gap 
between skilled workers and employers in India. The platform provides a 
bilingual (English/Hindi) interface that enables workers to find employment 
opportunities and allows employers to discover skilled labor efficiently. 

The application features real-time job postings, application tracking, profile 
management, community features, and analytics dashboards for both user types. 
Built using React Native with Expo framework and Supabase backend, the system 
ensures scalability, security, and cross-platform compatibility.

================================================================================
CHAPTER 1: INTRODUCTION
================================================================================

1.1 PROBLEM STATEMENT
---------------------
The informal labor sector in India faces significant challenges in connecting 
skilled workers with potential employers. Traditional methods of job searching 
are inefficient, lack transparency, and often exclude workers who are not 
digitally literate. There is a critical need for a user-friendly, bilingual 
platform that can facilitate this connection while ensuring security and 
reliability.

1.2 OBJECTIVES
--------------
- Develop a mobile application accessible to both workers and employers
- Provide bilingual support (English and Hindi) for wider accessibility
- Enable real-time job posting and application management
- Implement secure authentication and data management
- Create community features for worker networking
- Provide analytics and insights for both user types
- Ensure cross-platform compatibility (Android and iOS)

1.3 SCOPE
---------
The application covers:
- User registration and authentication for workers and employers
- Profile management with skill-based matching
- Job posting, searching, and filtering
- Application submission and tracking
- Document management for workers
- Community creation and management
- Real-time notifications
- Analytics dashboards
- Multi-language support

3. employer_profiles

   - company_name (TEXT)
   - company_logo (TEXT)
   - industry (TEXT)

   - created_at (TIMESTAMP)

4. jobs
   - id (UUID, PK)
   - title (TEXT)
   - description (TEXT)
   - city (TEXT)
   - area (TEXT)
   - salary_range (TEXT)
   - required_skills (TEXT[])
   - workers_needed (INTEGER)
   - work_type (TEXT)
   - duration (TEXT)
   - expiry_date (DATE)
   - is_active (BOOLEAN)
   - created_by (UUID, FK to users)
   - created_at (TIMESTAMPTZ)

5. applications
   - id (UUID, PK)
   - job_id (UUID, FK to jobs)
   - worker_id (UUID, FK to users)
   - status (TEXT)
   - expected_pay (TEXT)
   - applied_at (TIMESTAMPTZ)

6. communities
   - id (UUID, PK)
   - name (TEXT)
   - description (TEXT)
   - created_by (UUID, FK to users)
   - max_members (INTEGER)
   - created_at (TIMESTAMP)

7. community_members
   - id (UUID, PK)
   - community_id (UUID, FK to communities)
   - worker_id (UUID, FK to users)
   - joined_at (TIMESTAMP)

8. notifications
   - id (UUID, PK)
   - user_id (UUID, FK to users)
   - title (TEXT)
   - message (TEXT)
   - type (TEXT)
   - read (BOOLEAN)
   - created_at (TIMESTAMP)

9. documents
   - id (UUID, PK)
   - worker_id (UUID, FK to users)
   - document_type (TEXT)
   - document_url (TEXT)
   - status (TEXT)
   - uploaded_at (TIMESTAMP)

10. bookmarks
    - id (UUID, PK)
    - worker_id (UUID, FK to users)
    - job_id (UUID, FK to jobs)
    - created_at (TIMESTAMP)

11. app_settings
    - id (UUID, PK)
    - key (TEXT, UNIQUE)
    - value (TEXT)
    - created_at (TIMESTAMPTZ)
    - updated_at (TIMESTAMPTZ)

4.2.2 Relationships:
- One-to-One: users ↔ worker_profiles, users ↔ employer_profiles
- One-to-Many: users → jobs, users → communities, jobs → applications
- Many-to-Many: workers ↔ communities (via community_members)

5.4 DATABASE IMPLEMENTATION
---------------------------

5.4.1 Row Level Security Policies:

Example for jobs table:
- SELECT: Anyone can view active jobs
- INSERT: Only authenticated employers can create jobs
- UPDATE: Only job creator can update
- DELETE: Only job creator can delete

Example for applications table:
- SELECT: Workers see their own, employers see applications to their jobs
- INSERT: Only authenticated workers can apply
- UPDATE: Only employer can update status

5.4.2 Database Functions:
- notify_community_join(): Trigger function for community notifications
- update_updated_at_column(): Auto-update timestamp trigger

5.4.3 Indexes:
- jobs(created_by, is_active, expiry_date)
- applications(worker_id, job_id, status)
- community_members(community_id, worker_id)

APPENDIX B: DATABASE MIGRATIONS
================================================================================

B.1 Create Jobs Table:
```sql
CREATE TABLE jobs (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT NOT NULL,
  city TEXT NOT NULL,
  area TEXT,
  salary_range TEXT,
  required_skills TEXT[],
  workers_needed INTEGER DEFAULT 1,
  work_type TEXT,
  duration TEXT,
  expiry_date DATE NOT NULL,
  is_active BOOLEAN DEFAULT true,
  created_by UUID REFERENCES auth.users(id),
  created_at TIMESTAMPTZ DEFAULT now()
);
```

B.2 Enable Row Level Security:
```sql
ALTER TABLE jobs ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Anyone can view active jobs"
ON jobs FOR SELECT
USING (is_active = true);

CREATE POLICY "Employers can create jobs"
ON jobs FOR INSERT
WITH CHECK (auth.uid() = created_by);
```
